# 0001 - 消除平滑滚动的起步阻力

- **状态**: Implemented
- **创建日期**: 2026-09-01
- **最后更新**: 2026-09-23
- **所属愿景**: 无
- **配套文档**: 无

## 摘要

每次从静止开始滚动时, 前几帧的输出被 `ScrollFilter` 显著压低 (首帧输出 0, 前 5 帧只发出应有位移的 41%),
表现为"起步有一段阻力, 要多滚几下才顺". 同一个滤波器还让每次滚动的总位移只有目标值的 87% ——
滚动在增量低于精度门限时被 `stop` 截断, 滤波器记忆里未输出完的量被直接丢弃.

根因是 `ScrollFilter` 是一个记忆初值为 0 的指数移动平均 (系数 0.23), 对"从静止起步"这种阶跃输入
必然存在上升时间. 但它不能简单删除: 实测它在连续滚动时把慢速滚动的速度纹波从 72.5% 压到 20.1%,
去掉会产生明显的搏动感.

本提案把平滑从**输出侧**移到**输入侧**: 起步的第一个滚轮增量全额进入缓冲区不做平滑, 滚动途中的
增量先进入待注入池再逐帧释放. 滤波器分不清"起步阶跃"和"滚轮 tick 跳变", 但 `ScrollPoster` 分得清 ——
`update` 本来就知道这次是重置缓冲区 (起步/反向) 还是累加 (途中).

## 方案

### 新增 `ScrollAccumulator`

单轴的滚动距离累积器, 是一个不依赖 `CVDisplayLink` / `CGEvent` 的纯值类型, 承担原先散在
`ScrollPoster` 里的 `buffer` / `current` / `delta` 三元组逻辑, 并作为本次改动的测试接缝:

| 成员 | 职责 |
|------|------|
| `accept(delta:scaledBy:)` | 接收一次滚轮输入. 同向累加时增量进入 `pendingInjection`; 起步或反向时全额写入 `buffer` 并清空待注入池 |
| `advance(transition:)` | 推进一帧: 先按 `injectionRate` 从待注入池释放一部分进 `buffer`, 再做线性插值, 返回本帧位移 |
| `hasSettled(precision:)` | 本帧位移与待注入残留同时低于门限时才算收敛, 避免截断掉尚未注入的距离 |
| `brake()` / `reset()` | 刹车 (停在当前位置) 与重置, 均清空待注入池 |

`ScrollPoster` 持有垂直 / 水平两个实例, 不再调用 `ScrollFilter`. `ScrollFilter.swift` 随之删除.

### 已否决: 分摊强度随输入密集程度自适应

固定分摊率对"大力滚"的惩罚最重: 大力滚时两格之间只隔两三帧, 待注入池来不及释放就又堆进来一格,
越滚越滞后; 慢慢滚时两格隔得久, 池子早就放完了, 反而正常. 据此试过让立即生效的比例随距上次输入的
帧数变化 —— 2 帧以内全额生效, 8 帧以外全部分摊, 中间线性过渡.

起步阻力确实进一步减小 (大力滚 100ms 内的累计滚动距离 93 → 133, 原 ScrollFilter 是 48),
但实机反馈"滚动一顿一顿的": 密集输入少分摊, 等于把速度纹波放了回来, 中速档的稳态纹波从 16.4% 涨到 32.0%.

**结论: 起步跟手与滚动顺滑在这一层是此消彼长的, 不存在两头都要的调参空间.**
用户在两者之间选择了顺滑, 因此回退到对所有同向输入一视同仁的固定分摊.
若日后仍要压低起步阻力, 应当去动插值曲线本身 (平滑时长设置), 而不是继续加工分摊策略.

### 参数选取

`injectionRate` 取 0.25 (每帧释放待注入池的 25%), 只作用在稀疏输入上. 与改动前的对照实测:

| | 起步前 6 帧输出 / 理想 | 快滚纹波 | 中速纹波 | 慢滚纹波 | 单次滚动总位移 |
|---|---|---|---|---|---|
| 现状 (ScrollFilter) | 0% 27% 50% 71% 90% 106% | 7.7% | 9.4% | 20.1% | 87% |
| 本方案 (rate 0.25) | 100% 全程贴合理想曲线 | 4.0% | 6.1% | 18.5% | 94% |

94% 是精度门限截断后的无损上限 (理想曲线本身就是 94%), 即位移不再有额外损耗.
纹波三档全面优于现状. rate 越小纹波越低但途中加速响应越钝, 0.20–0.30 都可接受, 取中值.

### 未做的假设与取舍

- **不加开关**: 用户明确要求直接改死, 不保留新旧实现的切换常量.
- **不动 UI 与配置项**: `injectionRate` 是代码内常量, 不暴露到偏好设置.
- **顺带修复方向反转**: 现状下滚动途中反向需要 4 帧才真正掉头 (滤波器要跨过零点),
  新方案的反向走"全额写入"分支, 首帧即刻响应. 这不是独立改动, 是同一处逻辑的自然结果.
- **不同步上游 4.x**: 上游最新版 (4.3.0-beta) 的 `ScrollFilter` 与本仓库逐字相同, 没有可借鉴的修复.

### 验证

新建 `MosTests` 单元测试 target, 针对 `ScrollAccumulator` 断言行为规格: 起步首帧全额响应、
途中增量不立即全额并入、总位移守恒、反向立即掉头、刹车即停. 期望值取独立推导的已知值,
不复算实现. 手感由 Mos 自带的 Event Monitor (按住 Option 点击菜单栏图标) 观察滚动曲线复核.
